# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

- `npm run dev` — start the Vite dev server
- `npm run build` — production build to `dist/`
- `npm run preview` — preview the production build locally
- `npm run docs` — regenerate `docs/` from `src/` (see Documentation below)

No lint or test setup exists in this repo. `npm run build` succeeding is the only correctness check before pushing.

## Folder structure

```
index.html                 Vite entry point
src/
  main.jsx                 ReactDOM root render
  App.jsx                  Tab shell (About / Research / Projects / CV), local useState, no router
  index.css                Tailwind directives + custom @layer utility classes
  components/              one component per file
public/                    static passthrough dir → copied to dist/ root; referenced by absolute
                            path from components (/img/*, /BUET-Curriculum.html, /utd-Curriculum.html)
docs/                       generated documentation — do not hand-edit, see Documentation below
scripts/generate-docs.js   orchestrator: walks src/, calls docgen/, writes docs/
scripts/docgen/            parse.js (extraction), graph.js (import-reachability), render.js (markdown)
assets/, forms/,            dead legacy Bootstrap "Kelly" CV template — not part of the Vite build,
BUET-Curriculum.html (root) not referenced by src/ or index.html. Don't extend; prefer removing.
dist/                       gitignored local build artifact, not tracked in git
```

## Conventions

- Function components only (`export default function Name() {}`); no class components, no TypeScript, no router.
- Page sections are tabs held in `App.jsx`'s local `useState`, not routes.
- No CMS/API/markdown: page content is hardcoded JS arrays/objects inside the component that renders it (e.g. `About.jsx`'s `INTERESTS`, `SKILL_GROUPS`, `NEWS`).
- Styling is Tailwind utility classes only — no CSS modules, no styled-components. Custom tokens (brand color, font) live in `tailwind.config.js`.
- `src/components/Hero.jsx`, `Research.jsx`, `News.jsx`, `Skills.jsx` are orphaned — not imported anywhere. Don't assume edits to them affect the live site.

## Documentation

`docs/` is generated by `npm run docs` (`scripts/generate-docs.js` + `scripts/docgen/`) from `src/**/*.{js,jsx}`. Never hand-edit anything under `docs/` — edit the source file and re-run the generator instead. Re-run it after adding a component, renaming one, changing its props, or changing what imports what.

Per file it reports: description (from a leading `/** ... */` block, else a fallback based on the JSX root element's `id`), imports, **exports vs. internal (non-exported) helpers** as separate sections, local `UPPER_CASE` data constants, and — via `scripts/docgen/graph.js` walking the import graph from `src/main.jsx` — an **"Imported by" list** plus a **`⚠ Not imported anywhere` banner** (and an `⚠` in the index table) for files unreachable from the entry point. This is how `Hero.jsx`, `Research.jsx`, `News.jsx`, `Skills.jsx` get flagged as dead code automatically instead of relying on this doc to say so.

The generator is regex-based (`scripts/docgen/parse.js`), not an AST parser, so write source in the forms it understands: a component is `export default function Name(props) {}`, `export function Name(props) {}`, `export const Name = (props) => {}`, or a non-exported local helper as either `function Name(props) {}` or `const Name = (props) => {}`. Destructured props (`{ a, b }`) are rendered as such in signatures, not as positional args.

## Deployment

`.github/workflows/deploy.yml` builds and deploys on every push to `main` (or manual `workflow_dispatch`): `npm ci` → `npm run build` → upload `dist/` → `actions/deploy-pages`. The workflow sets `concurrency: {group: pages, cancel-in-progress: true}` to prevent overlapping/queued Pages deployments — keep this if editing the workflow. There is no CNAME; the site serves at the default `ajoydey00001.github.io`.
